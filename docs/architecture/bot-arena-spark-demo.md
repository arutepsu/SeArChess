# Bot Arena + Spark: Local Demo Pipeline

## Purpose

Runs a complete end-to-end demo on a single machine:

1. Heuristic bots play a round-robin tournament; events are streamed to a JSONL file.
2. Spark reads that file and prints a leaderboard, head-to-head results, termination
   reason distribution, and average game length.

This is the first working slice of the Bot Evaluation Arena analytics pipeline.
No Kafka, no database, no UCI engines, no SearchessAI — batch-only, local-only.

---

## Step 1 — Generate tournament JSONL

```
sbt demoHeuristicTournament
```

Default output: `target/arena/heuristic-tournament/game-events.jsonl`

The file is deleted and recreated on each run (no append).

Bots: `random-bot`, `capture-first`, `material-greedy`  
Matchups: 6 (3 bots × 2 directions × 1 repetition)  
Max ply per game: 500 (terminates as draw if reached)

Optional arguments (overrides defaults):

```
sbt "arenaDemoHeuristic/run <outputPath> [repetitions] [maxPlyPerGame]"
```

Examples:

```
sbt "arenaDemoHeuristic/run target/arena/demo.jsonl 2 200"
```

---

## Step 2 — Run Spark analytics

```
sbt demoSparkAnalytics
```

Default input:  `target/arena/heuristic-tournament/game-events.jsonl`  
Default output: `target/spark-analytics/`

Results are printed to the console. CSV parts are written under the output directory:

```
target/spark-analytics/
  leaderboard/       ← sorted by total score
  head-to-head/      ← win/draw/loss per ordered (white, black) pairing
  terminations/      ← count per termination reason
  avg-game-length/   ← avg ply and avg duration per pairing
```

Optional arguments (overrides defaults):

```
sbt "sparkAnalytics/run <inputPath> <outputPath>"
```

## Java 21 / Spark 3.5.x notes

Spark 3.5.x is certified on Java 17; Java 21 support is partial.  
The `sparkAnalytics` sbt module adds 14 `--add-opens` flags (see `sparkJvmOpens`
in `build.sbt`) for both `run` and `Test` scopes. These cover Spark's main
reflection paths.

If you see `InaccessibleObjectException` with an unfamiliar module, add:
```
"--add-opens=<module>/<package>=ALL-UNNAMED"
```
to `sparkJvmOpens` in `build.sbt`.

**Recommended JDK for Spark 3.5.x**: Java 17.  
**Clean Java 21 path**: Spark 4.0 (Scala 2.13 only; API-compatible for SQL usage).

### Windows: hostname resolution

The Spark driver bind address is forced to `127.0.0.1` in `GameAnalyticsJob`
and in `GameAnalyticsSpec` to avoid hostname-resolution failures on Windows.

### Windows: CSV write and `winutils.exe`

Spark's Hadoop output committer calls `chmod` via `winutils.exe` when writing files on
Windows. Without it, the CSV write fails with `HADOOP_HOME and hadoop.home.dir are unset`.

The analytics tables are **always printed to the console** regardless of this failure.
`GameAnalytics.run` catches the exception and prints a `[WARN]` instead of crashing.

To enable CSV output on Windows:
1. Download `winutils.exe` for your Hadoop version from a trusted source.
2. Place it in a directory, e.g. `C:\hadoop\bin\winutils.exe`.
3. Set `HADOOP_HOME=C:\hadoop` (and optionally `hadoop.home.dir` system property)
   before running the Spark job.

Alternatively, run on Linux/Mac where no native library is needed.

## Module map

```
arenaBotsHeuristic ──► arenaCore ──► arenaEvents
       │
arenaDemoHeuristic ──► arenaWriterJsonl ──► arenaEvents
                                │
                    (writes JSONL file)
                                │
                         sparkAnalytics ──► reads raw JSONL (no Scala 3 deps)
```

`sparkAnalytics` has no compile dependency on any arena Scala 3 class.
It reads JSONL as raw JSON via Spark's reader and filters by `eventType`.

Optional Stockfish tournaments use `arenaBotsUci` and write the same JSONL
event schema. See `docs/architecture/uci-stockfish-integration.md` for
Stockfish setup, demo commands, and the optional integration-test behavior.
